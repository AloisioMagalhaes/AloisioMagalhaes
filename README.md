## Como Trabalho (Metodologia)

### Ciclo de Desenvolvimento Solo com Qualidade
Quando desenvolvo sozinho, uso documentação e métricas como substitutos
para o controle de qualidade que equipes maiores têm com code review formal:

1. **Threat Modeling** antes de implementar features com dados sensíveis
2. **Testes automatizados** — cobertura mínima de 80% em lógica de negócio
3. **CI com gates de segurança** — não mergeia se SAST/DAST falhar
4. **Métricas de código** — complexidade ciclomática < 10, duplicação < 3%
5. **Changelog versionado** — Conventional Commits + semantic versioning
6. **Runbooks** para incidentes — documentação viva do que fazer quando algo quebra
7. **Privacy impact assessment** antes de coletar qualquer dado pessoal
